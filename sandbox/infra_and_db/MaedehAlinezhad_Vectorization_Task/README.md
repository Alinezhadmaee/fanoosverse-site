# Data Vectorization Pipeline (Project Fanous)

Converts job-ad records into 768-dimensional normalized vectors with EmbeddingGemma and writes a
JSONL file that can be handed to Qdrant in a single step.

## Contract

- Only the `text` field is embedded. `role_title` is used only inside the mandatory prefix.
- Prefix sent to the model: `title: {role_title} | text: {text}`
  (falls back to `title: none | ...` when `role_title` is empty, matching the model's documented convention).
- Every other field (salary, location, experience, categories, tags, ...) is copied untouched into `payload`.
- Output line format:

```json
{"point_id": "<UUID>", "vector": [768 floats], "payload": {"document_id": "...", "role_title": "...", "text": "...", "...": "..."}}
```

## Files

| File | Purpose |
|------|---------|
| `gemma_vectorizer.py` | Pipeline: read, build prefix, embed, assign UUID, write JSONL, validate |
| `requirements.txt` | Python dependencies |
| `README.md` | This document |
| `vectors.jsonl` | Final output (generated by running the script, see below) |

## Setup

1. Python 3.10+ and a virtual environment.
2. `pip install -r requirements.txt`
3. Default model: `google/embeddinggemma-2` (Apache-2.0, multimodal, 768-dimensional text embeddings).
   It is not license-gated, so login is not required. Use `--model` for another checkpoint or a local path.
4. The model ships a multimodal processor, so loading requires `pillow`, `torchvision` and `soundfile`
   (already listed in `requirements.txt`). If an import error names `torchcodec`, install it separately.
   Use `--text-only` to skip the vision and audio parts.
5. Do not run the model in float16: activations overflow. The default CPU float32 run is safe.

## Run

```bash
python gemma_vectorizer.py \
  --input main-processed-v3.jsonl \
  --output vectors.jsonl
```

Validate the result against the input:

```bash
python gemma_vectorizer.py --validate vectors.jsonl --input main-processed-v3.jsonl
```

Fix vector norms of an existing output without re-running the model (the model weights are bfloat16, so raw
norms can deviate by about 0.4% from 1.0 until they are renormalized in float64):

```bash
python gemma_vectorizer.py --renormalize vectors.jsonl --output vectors_fixed.jsonl
python gemma_vectorizer.py --validate vectors_fixed.jsonl --input main-processed-v3.jsonl
```

Pipeline smoke test without the model (fake deterministic vectors, never use for production):

```bash
python gemma_vectorizer.py --input main-processed-v3.jsonl --output /tmp/dry.jsonl --dry-run
```

## Options

| Option | Default | Meaning |
|--------|---------|---------|
| `--text-key` | `text` | Field to embed |
| `--title-key` | `role_title` | Field used in the prefix |
| `--id-key` | `document_id` | Field the UUID is derived from |
| `--uuid-mode` | `uuid5` | `uuid5` is deterministic per document id (safe to re-run and upsert); `uuid4` is random |
| `--dim` | `768` | Output dimension |
| `--batch-size` | `16` | Encoding batch size |
| `--device` | auto | `cpu`, `cuda` or `mps` |
| `--text-only` | off | Load only the text part of the multimodal model |
| `--drop-text-from-payload` | off | Omit `text` from payload to save space |
| `--dry-run` | off | Fake vectors for testing the pipeline |

## Implementation notes

- Vectors come from `sentence-transformers` and are then L2-normalized again in float64, so each has unit norm within 1e-3.
- The prefix is built manually (`title: {role_title} | text: {text}`), as the model card requires for titled documents.
- The script passes `prompt=""` to the encoder so no second prefix is added on top of the manual one.
- Tokens above the model's max sequence length are truncated by the model. The script logs how many documents were affected.
- `point_id` uses `uuid5` over `document_id` with a fixed namespace, so re-running yields identical IDs.
- Records without a usable `text` are skipped and logged. Duplicate point IDs abort the run.
- The validator checks: exact keys, valid and unique UUIDs, 768 finite floats, unit norm, and that the payload equals the input record.

## Qdrant handoff

Create the collection with `size=768` and `distance=Cosine`, then upsert each line as
`id=point_id`, `vector=vector`, `payload=payload`. Numeric and list fields in the payload keep their
original types, so exact filters (salary range, experience, categories) work.
