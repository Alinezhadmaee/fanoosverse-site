# Fanoos Project: Core RAG Sample Pipeline

## Overview
This directory contains the foundational end-to-end Retrieval-Augmented Generation (RAG) sample pipeline for the **Fanoos** project. It serves as the official architectural blueprint and testing ground for team members working on Data Validation, Text Vectorization, and Qdrant Vector Database Ingestion.

The pipeline demonstrates how raw job advertisement records are validated against a strict schema, selectively vectorized using Google's **EmbeddingGemma 2** (`google/embeddinggemma-2`), indexed into an HNSW-enforced **Qdrant** collection, and retrieved via semantic vector search.

---

## Repository File Structure & Architecture Deep-Dive

The pipeline is divided into **two persistent data artifacts** and **four modular Python scripts**[cite: 4]:

```text
AhmadrezaHashemi_RAGSampleConfiguration/
├── .env                          # Local secrets & configuration (NEVER commit to Git!)
├── sample_raw_data.jsonl         # Raw input dataset (Unvalidated job advertisements)
├── Vectorized_raw_data.jsonl     # Persisted output artifact (UUIDs + 768-d Vectors + Payloads)
├── Pydantic_schema_verified.py   # Strict data contract and metadata filter
├── Embedding_process.py          # Streaming line-by-line Gemma 2 vectorization engine
├── Qdrant_configuration.py       # HNSW database setup, batch ingestion, and query testing
├── main.py                       # Central pipeline orchestrator
└── README.md                     # Documentation and setup guide
```

### 1. Why `sample_raw_data.jsonl` is Included
`sample_raw_data.jsonl` acts as our standardized local testbed[cite: 4]. It contains realistic, detailed Iranian job advertisement records with mixed Persian/English text and structured metadata. 
* **Decoupled Testing:** Including this file allows teammates working on the RAG, Embedding, and Vector Database layers to test their code immediately without needing to run the live web scraper first.
* **Memory-Safe Streaming Design:** Real job descriptions are text-heavy. Rather than loading an entire JSON array into RAM at once—which causes Out-Of-Memory (OOM) crashes at scale—this file is formatted as **JSON Lines (`.jsonl`)** so the pipeline can stream and process strictly **one job advertisement per line** inside a loop.

### 2. Why `Vectorized_raw_data.jsonl` is Included and Persisted
`Vectorized_raw_data.jsonl` is the intermediate handoff artifact produced by `Embedding_process.py`[cite: 4]. Each line is a self-contained JSON object containing:
* `point_id`: A unique UUIDv4 string.
* `vector`: A normalized 768-dimensional float array generated by `google/embeddinggemma-2`.
* `payload`: The validated, unvectorized metadata dictionary.

**Why we keep this file in the repository instead of deleting it after execution:**
1. **Compute Savings for Database Testing:** Running the neural embedding model over raw text is the slowest and most hardware-intensive step of the pipeline. By persisting `Vectorized_raw_data.jsonl` in the repo, teammates working on `Qdrant_configuration.py` (tuning HNSW graph parameters, payload indexes, or search filters) can run `python Qdrant_configuration.py` directly and ingest data into Qdrant in milliseconds—without waiting to download or run the 740M-parameter embedding model.
2. **Single-File Append Architecture:** When `Embedding_process.py` runs, it processes `sample_raw_data.jsonl` line-by-line and appends (`'a'` mode) every processed record into this single consolidated file, avoiding file fragmentation while keeping RAM usage near zero.

---

### 3. Python Modules Breakdown

#### `Pydantic_schema_verified.py` (The Data Gatekeeper)
Defines the `VectorStorePayload` Pydantic model[cite: 4]. This module serves two critical purposes:
* **Strict Filtering (The Pydantic Shield):** Raw scraped data often contains noisy or irrelevant keys. When `VectorStorePayload.model_validate()` parses a raw JSON line, it automatically strips out any field not explicitly declared in the schema.
* **Type Enforcement & Safe Defaults:** Enforces that required RAG context strings (`text`, `role_normalized`, `organization`) exist, validates integer fields (`salary_min`, `salary_max`, `experience_years_min`), converts missing categorical arrays (`skills_required`, `tools`, `seniority`) into safe empty lists `[]`, and drops `None` values via `exclude_none=True` so Qdrant payloads stay clean.

#### `Embedding_process.py` (The Vectorization Engine)
Handles model initialization and selective text embedding[cite: 4]:
* **Selective Vectorization Rule:** Structured metadata (`location`, `salary_min`, `industry`, `tools`, etc.) is **never** passed to the embedding model. Embedding numbers and hard tags degrades semantic vector quality. Instead, this module extracts **only** `role_normalized` and `text` for vectorization, while passing all other validated fields untouched into the `payload` dictionary.
* **Mandatory Indexing Prefix:** Formats the extracted text using EmbeddingGemma 2's asymmetric document prompt:
  ```text
  title: {role_title} | text: {raw_text}
  ```
* **Normalized Output:** Calls `model.encode(..., normalize_embeddings=True)` to produce unit-length 768-dimensional vectors optimized for Cosine similarity, writing each result immediately to `Vectorized_raw_data.jsonl`.

#### `Qdrant_configuration.py` (Storage & HNSW Retrieval Engine)
Manages the lifecycle of the Qdrant vector database and simulates production RAG retrieval[cite: 4]:
* **Collection & Forced HNSW Setup:** Creates `lantern_sample_collection` configured for `size=768` and `Distance.COSINE`. It explicitly configures `HnswConfigDiff(m=16, ef_construct=100, full_scan_threshold=10)`. Setting `full_scan_threshold=10` (the minimum valid KB threshold in modern Qdrant) forces the engine to construct and traverse the HNSW graph even on our small 10-line sample dataset rather than falling back to brute-force scanning.
* **Payload Indexing & Batch Upsert:** Creates a keyword payload index on `location` for fast pre-filtering and ingests `Vectorized_raw_data.jsonl` in memory-safe batches of 100 points.
* **Asymmetric Query Testing:** Embeds a sample natural language query using the mandatory retrieval prefix (`task: search result | query: {user_query}`) and queries Qdrant via the modern `client.query_points()` API (`qdrant-client >= 1.16`) with `SearchParams(hnsw_ef=128)`.

#### `main.py` (The Central Orchestrator)
The single entrypoint that ties all modules together[cite: 4]:
* Verifies that `sample_raw_data.jsonl` exists in the working directory.
* Sequentially executes **Step 1** (`process_and_vectorize`), **Step 2** (`setup_and_ingest`), and **Step 3** (`run_retrieval_test`).
* Handles exceptions gracefully at every stage, logs execution time, and guarantees `qdrant_client.close()` is called on shutdown.

## Understanding `HF_TOKEN` (Why It Is Required & How to Get It)

In our `.env` configuration, you will see a required variable named `HF_TOKEN`.

### Why is `HF_TOKEN` required?
We use Google's **`google/embeddinggemma-2`** model hosted on Hugging Face. Although Gemma models are free and open-weights, they are stored in **gated repositories**. Hugging Face blocks anonymous downloads with a `401 Client Error (Unauthorized)` unless your script provides an authentication token proving that your Hugging Face account has accepted Google's license terms.

### How to get your `HF_TOKEN` (2 Minutes):
1. Create a free account or log in at [huggingface.co](https://huggingface.co/).
2. Visit the model page: [https://huggingface.co/google/embeddinggemma-2](https://huggingface.co/google/embeddinggemma-2)
3. Click the **"Acknowledge license"** / **"Agree and access repository"** button on the model card.
4. Go to your Hugging Face **Settings -> Access Tokens**: [https://huggingface.co/settings/tokens](https://huggingface.co/settings/tokens)
5. Click **"Create new token"**, select the **Read** role, give it a name (e.g., `fanoos-rag`), and copy the generated token (it starts with `hf_...`).
6. Paste that token into your local `.env` file as `HF_TOKEN=hf_...`. When our scripts run `load_dotenv()`, `SentenceTransformer` automatically detects `HF_TOKEN` in the environment and authenticates your download.

## PC Prerequisites & Exact Installation Guide

Ensure you are running **Python 3.12+** inside an isolated virtual environment (`venv` or `conda`).

### Why Special Dependencies Are Required for `embeddinggemma-2`
`google/embeddinggemma-2` uses the `EmbeddingGemma2Processor` architecture inside Hugging Face `transformers`. Because EmbeddingGemma 2 is built on a multimodal backbone, importing its processor automatically imports vision and audio processing utilities (`torchvision`, `pillow`, `scipy`, `librosa`). 

If `torch` and `torchvision` have mismatched versions, or if `transformers` is outdated, Python will crash on startup with `Could not import module 'EmbeddingGemma2Processor'` or `RuntimeError: operator torchvision::nms does not exist`.

### Step-by-Step Installation Commands

Run these exact commands in your activated terminal to guarantee 100% version alignment:

```bash
# 1. Upgrade pip
pip install --upgrade pip

# 2. Install aligned PyTorch, Torchvision, and Torchaudio (Lightweight CPU build ~180MB)
# Note: If you have a dedicated NVIDIA GPU and want CUDA, omit the --index-url flag.
pip install --upgrade torch torchvision torchaudio --index-url [https://download.pytorch.org/whl/cpu](https://download.pytorch.org/whl/cpu)

# 3. Install core RAG, validation, and Qdrant packages
pip install --upgrade pydantic python-dotenv qdrant-client

# 4. Install multimodal processor dependencies required by EmbeddingGemma2Processor
pip install --upgrade pillow librosa scipy accelerate hf_transfer

# 5. Install the latest Sentence-Transformers and bleeding-edge Hugging Face Transformers
pip install --upgrade sentence-transformers
pip install --upgrade git+[https://github.com/huggingface/transformers.git](https://github.com/huggingface/transformers.git)
```

### Verify Your Environment
Run this one-liner in your terminal to confirm `EmbeddingGemma2Processor` loads without binary conflicts:

```bash
python -c "from transformers import EmbeddingGemma2Processor; print('Processor loaded successfully')"
```

## Configuring `.env` and Running Qdrant

### 1. Create Your `.env` File
Create a file named `.env` in the root of this directory[cite: 4] (**never commit `.env` to GitHub**). Copy and paste the following template:

```env
# Hugging Face Authentication Token (Required for gated Gemma models)
HF_TOKEN=hf_YourActualTokenHere

# Official Google EmbeddingGemma 2 Model (Outputs 768-dim vectors)
EMBEDDING_MODEL_NAME=google/embeddinggemma-2

# Qdrant Database Connection Settings
QDRANT_HOST=localhost
QDRANT_PORT=6333
QDRANT_LOCAL_PATH=./qdrant_local_storage
```

### 2. Start the Qdrant Vector Database
To test true HNSW graph indexing and payload index creation, run the official Qdrant server via Docker:

```bash
docker run -d -p 6333:6333 --name fanoos_qdrant qdrant/qdrant:latest
```
*(Note: If you do not have Docker installed, you can switch `QdrantClient` in `Qdrant_configuration.py` to use `QdrantClient(path=QDRANT_LOCAL_PATH)` for zero-setup local disk testing, though local disk mode emulates search via brute-force NumPy rather than the Rust HNSW graph).*

## Execution Guide & Network Troubleshooting

### Run the Full Pipeline (`main.py`)
To run validation, vectorization, ingestion, and retrieval end-to-end:

```bash
python main.py
```

### Run Individual Modules Standalone
Because every script uses `if __name__ == "__main__":` guards, you can run any step independently:

```bash
# Test Pydantic schema validation only
python Pydantic_schema_verified.py

# Run only the embedding step (generates Vectorized_raw_data.jsonl)
python Embedding_process.py

# Run only Qdrant ingestion & search (reads existing Vectorized_raw_data.jsonl)
python Qdrant_configuration.py
```

### Troubleshooting Network & Proxy Issues (Iran Network Environment)
If downloading the model weights from Hugging Face stalls or runs at `<20 kB/s`, or if Qdrant throws `[Errno 111] Connection refused` while your proxy is active:

1. **Route Hugging Face through your local proxy while bypassing `localhost` for Qdrant:**
   ```bash
   # Replace 10809 with your local proxy's HTTP inbound port
   export http_proxy="[http://127.0.0.1:10809](http://127.0.0.1:10809)"
   export https_proxy="[http://127.0.0.1:10809](http://127.0.0.1:10809)"
   
   # CRITICAL: Prevent httpx/Qdrant from routing localhost database traffic into the proxy
   export no_proxy="localhost,127.0.0.1"
   export NO_PROXY="localhost,127.0.0.1"
   
   # Enable multi-threaded Rust downloads for Hugging Face
   export HF_HUB_ENABLE_HF_TRANSFER=1
   ```
2. Now run `python main.py`.
