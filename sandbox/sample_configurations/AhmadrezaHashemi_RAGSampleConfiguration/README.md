# Fanoos Project: Core RAG Sample Pipeline

## Overview
This directory contains the foundational end-to-end sample pipeline for the **Fanoos** project. It serves as the official architectural reference for team members working on Data Validation, Data Vectorization, and Qdrant Vector Database Ingestion. 

The pipeline demonstrates how raw job advertisement data is validated, selectively vectorized using **EmbeddingGemma 2**, stored in an HNSW-indexed **Qdrant** collection, and queried using semantic vector search.

---

## Architecture & Module Breakdown

The sample pipeline is strictly modularized into four core Python scripts and two data artifacts:

1. **`sample_raw_data.jsonl`**: The raw input file containing unvalidated job advertisement records.
2. **`Pydantic_schema_verified.py`**: Defines the `VectorStorePayload` class. It acts as a strict filter that strips out unwanted raw fields and enforces data types before vectorization.
3. **`Embedding_process.py`**: Reads the raw data line-by-line to prevent memory overflow (OOM). It extracts **only** the `role_normalized` and `text` fields, applies the mandatory Gemma 2 indexing prefix (`title: {role_title} | text: {raw_text}`), generates a normalized 768-dimensional float vector, and appends the output (UUID, vector, and unvectorized metadata payload) to `Vectorized_raw_data.jsonl`.
4. **`Vectorized_raw_data.jsonl`**: The intermediate handoff artifact generated by the embedding script, containing pre-computed vectors and structured payloads ready for database ingestion.
5. **`Qdrant_configuration.py`**: Connects to the Qdrant engine, configures the collection (`size=768`, `Distance.COSINE`), forces HNSW graph indexing (`full_scan_threshold=0`), builds payload indexes for hard filtering, batch-ingests the JSONL records, and executes a test semantic query using the `client.query_points()` API.
6. **`main.py`**: The central orchestrator that executes the entire workflow sequentially from raw data validation to final retrieval testing.

---

## Key Architectural Rules Enforced

* **Selective Vectorization (Text vs. Metadata):** Structured metadata fields (such as `location`, `salary_min`, `seniority`, and `skills_required`) are **never** passed to the embedding model. Only the natural language description (`text`) and job title (`role_normalized`) are vectorized. All other validated fields are stored intact inside the Qdrant `payload` for exact mathematical and categorical filtering.
* **Mandatory Prefix Formatting:**
  * **Document Indexing Prefix:** `title: {role_title} | text: {raw_text}`
  * **Search Query Prefix:** `task: search result | query: {user_query}`
* **Zero Hardcoded Secrets:** All model names, tokens, and database connection parameters are dynamically loaded from a `.env` file.

## Prerequisites & Installation

Ensure you are running **Python 3.12+** inside a virtual environment.

### 1. Install Dependencies
Because `google/embeddinggemma-2` requires the latest architecture definitions, ensure both `sentence-transformers` and the core `transformers` library are fully updated:

```bash
pip install --upgrade pip
pip install pydantic python-dotenv qdrant-client
pip install --upgrade sentence-transformers
pip install --upgrade git+[https://github.com/huggingface/transformers.git](https://github.com/huggingface/transformers.git)
